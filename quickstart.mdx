## 1. Conecte o Stripe

Em **Integrações**, conecte por OAuth. O acesso é somente leitura: o Keep nunca
cria, altera nem cancela cobrança, e nenhum token seu é armazenado — as chamadas
usam a chave de plataforma com um cabeçalho identificando a sua conta.

## 2. Gere uma chave de API

Em **Chaves de API**, clique em **Nova chave** e dê um nome que você reconheça
daqui a seis meses. É por ele que você vai decidir qual revogar.

<Warning>
  O segredo aparece uma única vez. Guardamos apenas o hash, então nem nós
  conseguimos mostrá-lo depois. Se perder, gere outro e revogue o anterior.
</Warning>

## 3. Mande atividade

Uma chamada do seu backend, onde você já sabe quem é o usuário. Uma por login
costuma bastar.

<CodeGroup>

```bash cURL
curl -X POST https://usekeep.dev/api/v1/activity \
  -H "Authorization: Bearer kp_live_..." \
  -H "Content-Type: application/json" \
  -d '{"stripeCustomerId":"cus_ABC","email":"cliente@empresa.com"}'
```

```ts Node
await fetch("https://usekeep.dev/api/v1/activity", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.KEEP_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    stripeCustomerId: account.stripeCustomerId,
    email: user.email,
  }),
});
```

```python Python
import os, requests

requests.post(
    "https://usekeep.dev/api/v1/activity",
    headers={"Authorization": f"Bearer {os.environ['KEEP_API_KEY']}"},
    json={"stripeCustomerId": account.stripe_customer_id, "email": user.email},
)
```

</CodeGroup>

<Tip>
  Mandar o `stripeCustomerId` é o que faz o casamento ser exato: o mesmo id
  chega do outro lado, vindo do próprio Stripe. Só com e-mail, vale a heurística
  de domínio — que falha justamente quando quem paga não é quem usa.
</Tip>

## 4. Espere duas semanas

O Keep compara os últimos 7 dias contra os 7 anteriores. Antes de existirem duas
janelas, não há o que comparar.

Se você quiser resultado imediato, mande um backfill: o endpoint aceita um array
de até 500 eventos por chamada, com `at` no passado.

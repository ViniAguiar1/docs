---
title: "POST /v1/activity"
description: "Send your product's activity to Keep."
---

## Authentication

`Authorization: Bearer kp_live_...`, with a key generated in **API keys**. An
invalid or revoked key returns `401` without saying which — telling the
difference would confirm a key existed to whoever has the wrong one.

## Body

Accepts an object or an array of up to **500** events.

<ParamField body="customerId" type="string">
  The customer's id in your billing — `cus_...` on Stripe and Asaas, `cust_...`
  on AbacatePay. Preferred: it is what makes the match exact.
</ParamField>

<ParamField body="stripeCustomerId" type="string" deprecated>
  The old name for the same field, from when only Stripe existed. It still works
  and will keep working: breaking whoever already integrated would cost more
  than the wrong name. When both arrive, `customerId` wins.
</ParamField>

<ParamField body="email" type="string">
  The user's email. Used as the key when there is no `customerId`, and as a
  human label in the alert when there is.
</ParamField>

<ParamField body="at" type="string">
  ISO 8601. Assumes now when absent. Rejected if it is more than five minutes in
  the future, or more than 90 days in the past.
</ParamField>

<ParamField body="eventId" type="string">
  Optional, for you to deduplicate on your side. Not required.
</ParamField>

<Note>
  At least one of `customerId` and `email` is required. Without an identifier
  there is nothing to match, and the event is discarded.
</Note>

## Response

```json
{ "ok": true, "accepted": 12, "skipped": 1, "days": 3 }
```

`accepted` counts events used, `skipped` the ones discarded for a missing
identifier or a date outside the window, and `days` how many counter rows were
touched. One invalid item does not bring down the batch.

## What happens to what you send

We do not store the event. What arrives is summed into a **counter per account
and per day**, and it is that number we compare week over week.

We do not receive content, screens visited, IP address, or any browser
identifier — the call comes from your server, not from your users' browsers.

<Note>
  A resend counts twice, and that is fine: the drop threshold compares two weeks
  against each other, so uniform excess cancels out in the ratio.
</Note>

## Errors

| Code | When |
| --- | --- |
| `401` | Key missing, malformed, invalid, or revoked |
| `400` | Invalid JSON, empty body, batch over 500, or no usable event |
| `500` | Our failure to write. Worth retrying — a `4xx` is not |
